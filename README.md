# 하늘왕국 온라인 — 실제 온라인 멀티플레이 서버

Node.js + Express + WebSocket(`ws`) + SQLite 기반의 실행 가능한 프로젝트입니다.

## 요구 사항
- Node.js 20 이상
- npm
- 브라우저 2개 또는 기기 2대로 멀티플레이 테스트

## 설치 및 실행
1. ZIP 압축을 풉니다.
2. 프로젝트 폴더에서 `.env.example`을 `.env`로 복사합니다.
   - macOS/Linux: `cp .env.example .env`
   - Windows PowerShell: `Copy-Item .env.example .env`
3. `.env`에서 반드시 `JWT_SECRET`을 32자 이상의 무작위 문자열로 변경하고 `ADMIN_PASSWORD`를 14자 이상 강력한 비밀번호로 바꿉니다.
4. 설치 및 실행:
   ```bash
   npm install
   npm start
   ```
5. 브라우저에서 `http://localhost:3000` 접속합니다.
6. `.env`에 지정한 개발자 이름/비밀번호로 로그인합니다. 다른 플레이어는 계정을 만든 뒤 로그인합니다.

## 휴대폰만으로 테스트하기

이 프로젝트는 모바일 브라우저에 맞춘 반응형 화면과 큰 터치 버튼을 포함합니다. 다만 Node.js 서버를 일반 안드로이드 브라우저에서 직접 실행할 수는 없으므로, 휴대폰만 사용할 때는 서버를 먼저 온라인 호스팅에 배포해야 합니다.

1. 휴대폰 브라우저에서 GitHub 계정과 Railway 계정을 준비합니다.
2. 이 ZIP 파일을 GitHub 저장소로 올립니다. GitHub 모바일 웹에서 파일 업로드가 불편하면 ZIP을 지원하는 클라우드 개발 환경을 사용할 수 있습니다.
3. Railway에서 해당 저장소를 배포하고 환경 변수를 설정합니다. `NODE_ENV=production`, `DB_PATH=/data/skyrealm.sqlite`, 강력한 `JWT_SECRET`, 새 `ADMIN_USERNAME`, 새 `ADMIN_PASSWORD`를 사용하고 `/data` 영구 볼륨을 연결합니다.
4. Railway가 발급한 HTTPS 주소를 휴대폰 Chrome에서 엽니다.
5. 계정을 만들고 로그인한 뒤 이동, 채팅, 아이템, 친구 기능을 확인합니다. 멀티플레이는 같은 주소를 다른 브라우저나 다른 기기에서도 열어 확인합니다.
6. 게임 주소를 Chrome 메뉴에서 **홈 화면에 추가**하면 앱처럼 빠르게 열 수 있습니다. 이 기능은 바로가기이며, 서버 배포를 대신하지 않습니다.

참고: 이 프로젝트는 현재 모바일에 맞춘 2D 프로토타입입니다. 완성된 3D MMORPG는 아닙니다.

## Railway 배포 준비

이 저장소에는 Railway용 `Dockerfile`과 `railway.toml`이 포함되어 있습니다. Railway에서 서비스를 만든 뒤 환경 변수에 `NODE_ENV=production`, `PORT=3000`, `DB_PATH=/data/skyrealm.sqlite`, `JWT_SECRET`(32자 이상의 무작위 비밀값), `ADMIN_USERNAME`, `ADMIN_PASSWORD`를 설정하세요. `/data`에 영구 Volume을 연결해야 재배포 후 계정과 게임 데이터가 유지됩니다. `ADMIN_PASSWORD`에는 공개된 예시 비밀번호를 사용하지 말고 새롭고 강력한 값을 설정하세요. 배포 후 Railway에서 생성된 도메인을 공개하면 됩니다.

## 관리자 기능
관리자 패널에서 플레이어 검색, Kick, 영구 Ban, Unban, 골드/레벨 조정, 아이템 지급/회수, 서버 잠금/해제, 전 서버 공지, 감사 로그 조회를 할 수 있습니다. 관리자 API는 DB에서 사용자 역할을 다시 확인하므로 브라우저에서 role 값을 조작해도 권한을 얻을 수 없습니다.

## 보안 설계
- 비밀번호는 bcrypt로 해시 저장
- JWT는 HttpOnly 쿠키로도 발급, 짧은 만료 시간 적용
- 관리자 권한은 JWT의 role 클레임만 신뢰하지 않고 DB에서 재조회
- 관리자 API마다 `adminOnly` 미들웨어 적용
- 공개 WebSocket 메시지에서 관리자 명령을 거부
- 관리자 전용 아이템은 서버 카탈로그의 `adminOnly` 속성과 대상 역할로 검증
- 플레이어/아이템/서버 조작은 서버에서만 변경
- Ban 목록, 서버 잠금, 아이템, 골드/레벨, 친구, 감사 로그는 SQLite 영구 저장
- Express 보안 헤더, 요청 제한, JSON 크기 제한, WebSocket 페이로드 제한, 출처 검사
- `.env`, DB, `node_modules`는 Git에서 제외

## 관리자 계정 초기화
서버 최초 실행 시 `ADMIN_USERNAME` / `ADMIN_PASSWORD`를 사용해 관리자 계정을 생성합니다. 계정이 이미 있으면 해당 이름의 역할을 `admin`으로 복구합니다. 비밀번호를 바꿔야 한다면 계정 비밀번호 변경 절차를 별도로 구현하거나 개발 DB에서 해당 계정을 안전하게 재설정하세요. `.env`는 절대 공개 저장소에 올리지 마세요.

## 프로덕션 배포 전에 해야 할 일
이 코드는 실행 가능한 시작점이지, 대규모 상용 MMORPG에 대한 완성 보안 감사는 아닙니다.
- HTTPS/WSS 뒤에서 배포하고 `NODE_ENV=production`, `ALLOWED_ORIGINS=https://실제도메인` 설정
- `JWT_SECRET`을 비밀 관리 서비스에 저장하고 정기적으로 회전
- 운영 DB 백업, 마이그레이션, 모니터링 및 감사 로그 보존 정책 설정
- 관리자 계정 MFA, 로그인 실패 지연/잠금, 비밀번호 변경 및 복구 흐름 추가
- WebSocket 메시지별 속도 제한, 채팅 스팸/욕설 관리, 재접속/heartbeat 구현
- 월드/룸 샤딩과 다중 서버 배포 시 Redis Pub/Sub 또는 메시지 브로커로 전 서버 공지/플레이어 상태 브로드캐스트 구현
- 게임 경제에서 수정 수집 쿨다운과 서버 검증을 추가. 데모의 pickup 메시지는 실제 게임 규칙에 맞게 거리·쿨다운 검증을 강화해야 함.
- 친구 요청 수락 흐름, 아이템 거래/드롭 규칙, 운영 도구의 CSRF/Origin 정책을 실제 배포 설정에 맞춰 검토
- 의존성 취약점 점검: `npm audit`
- 보안 전문가 검토 및 자동 테스트

## 참고
현재 한 프로세스 내 접속자에게는 WebSocket broadcast가 동작합니다. 서버 여러 대에 걸친 진정한 전 서버 공지는 Redis 등 공용 pub/sub가 필요합니다. 관리자 전용 아이템은 개발자 계정 외에는 서버에서 지급/사용이 거부되며 전체 지급도 차단됩니다.


## 개발자 버튼 비밀번호
`.env.example`의 예시 비밀번호는 요청에 따라 `Sikuadmin123`으로 설정되어 있습니다. `.env`로 복사하면 개발자 버튼에서 이 비밀번호로 인증할 수 있습니다. 이 비밀번호는 대화에 노출되었고 길이도 짧으므로, 인터넷에 공개 배포하기 전에는 반드시 `.env`에서 고유하고 더 긴 비밀번호로 바꾸세요. 기존 `data/skyrealm.sqlite`에 이미 개발자 계정이 생성되어 있다면 `.env`의 비밀번호 변경만으로 기존 계정 비밀번호가 바뀌지 않습니다.
